# Architecture

Two Node processes share MongoDB and one protected DATA_DIR on one Ubuntu VPS. API serves HTTPS-authenticated vanilla dashboard, uploads, CRUD, persistent SSE and a transient browser login stream. Worker launches headless persistent contexts, executes FIFO jobs and saves original downloads and JSON. No Redis, Docker or frontend bundler.

Mongo models: singleton AdminUser, GoogleAccount, GeminiChat, GenerationJob, GeneratedOutput, Asset, ElementLocator, AutomationEvent, Lease and Setting. ObjectId references are checked at API boundaries. Unique idempotency keys include a request hash: reuse with a changed payload returns 409. Unique output job ID prevents two saved outputs for one job.

Queue claim sorts enqueuedAt and ObjectId (manual retries join the tail). Atomic global Mongo lease uses owner, monotonically increasing fence and expiry. Worker holds an OS flock for its entire lifetime, preventing a suspended old worker and replacement from generating concurrently on this VPS. All workers must share DATA_DIR; distributed workers on separate machines are unsupported. Job updates require owner and fence. Heartbeat failure closes browsers. Startup recovers unsubmitted jobs to queued and anything across submission boundary to needs_review. Cancellation after submission also needs review. No automatic prompt resubmission. Manual retries have a configurable budget and explicit ambiguity confirmation.

Account browser profiles use account ObjectId directories. Login and worker each acquire the same profile Mongo lease before Chromium startup. Chromium's profile singleton is additional OS-level protection. Heartbeat renewal failure closes the context. No CDP/VNC listeners. Login viewer exchanges JPEG frames and allowlisted mouse/keyboard input over authenticated same-origin WSS. Frame buffers are transient and excluded from monitoring/Groq. A configurable time limit (15 minutes by default, at most 30 minutes) bounds login. Verify checks a visible Gemini composer/sign-in UI and closes the context only after success; unsuccessful verification preserves the interactive browser. Transient navigation/capture errors do not close the stream, the client reconnects to the same browser after transport failures, and new allowed Google tabs become the active viewer page. This does not prove the display email is the Google identity: the admin must verify the selected identity during login.

Gemini adapter records response count before submission, scopes results to the newly appended response and uses its download action. It checks UI readiness/completion and supported download signatures/dimensions. A changed UI fails safely. Semantic locators / verified selectors precede compact Groq candidates; no model code execution or model-controlled URLs. Send is deliberately a single click after a durable submission marker and is not retried by the recovery ladder.

Mongoose indexes cover account/chat references, FIFO, unique keys and event TTL. Events are sanitized and replayed by ObjectId through SSE. The UI refreshes state after events and periodic status polls. Sensitive prompts appear only in authenticated jobs/metadata and never in events or recovery inputs. Monitoring exposes states, errors and worker-only current-response image crops; page/account text and login UI are excluded.

Consistency limitations: Mongo standalone does not provide file/database transactions. A crash between file write and output DB insertion can leave orphan files; operators must inspect them with services stopped. A persisted output is recovered as completed. Profile deletion and job enqueue are not a multi-document transaction; removing an account can race a newly submitted job, which fails as unavailable before browser work. Single VPS design is intentional.
