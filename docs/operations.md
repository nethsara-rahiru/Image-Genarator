# Operations

API and worker logs contain startup/status messages only, with sanitized persisted events. Check PM2 status, authenticated health/worker diagnostics and Jobs history first. Do not enable HTTP access logs with viewer query strings, capture login screenshots or dump environment variables.

**Login required:** Connect from Accounts and complete Google authentication directly. Session cookies can expire or be invalidated; never assume profile reuse guarantees authentication. Close old viewer before starting another login. If session viewer closes unexpectedly, reconnect; its TTL closes browser and releases profile lock.

**Needs review:** Inspect the saved Gemini conversation, determine whether submission occurred and whether a result exists. A retry may generate another image. Dashboard explicitly confirms this risk. No automatic retry after an ambiguous send. If a cancelled submitted job may have generated remotely, the local system cannot retract it.

**Worker offline:** Inspect Mongo connection, PM2 logs, flock conflicts, lease expiry and disk space. Only one worker and one runtime directory on this VPS. After a crash, let old processes die and lease expire; never manually remove live profile locks. Startup recovers uncertain jobs to needs_review. `pm2 stop gemini-worker` before filesystem maintenance.

**Selectors changed:** Inspect current Gemini UI manually, recovery events and verified locator revisions. Configure Groq only via server .env; text model must support structured JSON schema. Disabled/unconfigured recovery fails explicitly. Rollback restores the previous verified selector. No vision model is enabled. Monitor image crops stay local and are never sent to Groq. Never send login screens to a model. Attachment preview selectors and download controls especially require live UI validation.

**Retention:** Setting retentionDays controls hourly worker deletion of old outputs, unreferenced/non-active assets and events. Mongo TTL independently caps event expiry at 30 days. Finished job/chat metadata is retained for audit; remove/archive via UI as available. Retention does not erase Google conversations. Account removal deletes its local persistent profile after confirmation and archives local chats. Outputs remain independently until deletion/retention. Storage failures stop jobs; monitor filesystem free space externally.

## Consistent backup

As service user, `pm2 stop gemini-api gemini-worker`; wait for process exit. From the application directory run `npm run backup -- /opt/gemini-agent/backups`; the Node wrapper loads .env without printing secrets and passes a temporary protected configuration file to mongodump. Direct `scripts/backup.sh ABSOLUTE_DATA_DIR ABSOLUTE_BACKUP_DIR` is also available when MONGODB_URI is already exported. Back up `.env` separately into encrypted secret storage; it is excluded from runtime archive. Restart both PM2 apps. Encrypt backup archives before off-host transfer, restrict 0600 permissions and remove plaintext copies according to policy. Mongo dump is a standalone consistent backup only while app writes are stopped. A third-party DB writer would violate this assumption.

## Restore drill

On an isolated host with matching Node/Mongo/application versions, stop both services. Verify SHA256SUMS (paths in manifest refer to original backup location; adapt paths without changing hashes). Restore DB with `mongorestore --uri="$MONGODB_URI" --archive=database.archive.gz --gzip --drop` only into the intended restore database; this is destructive. Extract runtime archive into an empty 0700 runtime directory as gemini-agent. Restore .env through protected secret tooling. Remove stale worker.lock file only with all workers stopped (flock locks live on file descriptors, not file contents). Start API/worker, confirm account state and jobs; reconnect Google if required. Restored sessions may be revoked by Google. Do not run production and restored workers simultaneously against the same database/accounts. Record restore test evidence before production release.

## Login viewer recovery

Update to the login-viewer lifecycle fix when the viewer disconnects on Google Next/Sign in navigation. A screenshot failure is recoverable, and reconnecting reuses the existing profile context. Reconnect viewer retries only the stream; it does not create another browser or submit Google credentials again. Complete Google sign-in/2FA, use Open Gemini if still on an account page, wait for a visible Gemini prompt box, then Verify & finish. A failed check leaves the browser open. The displayed countdown defaults to 15 minutes; configure LOGIN_SESSION_MS in .env (1–30 minutes) and restart the API to change it. Expiry, revoked app authentication, a browser crash or loss of the profile lease remain terminal. Profile lease loss appears as a distinct event/status reason; inspect Atlas reachability and API health rather than disabling locks. No Google security checks are bypassed and live Google compatibility remains unverified.
