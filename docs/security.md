# Security and boundaries

One administrator, created/reset only through the VPS terminal. Argon2id hashes, hidden confirmed password entry, atomic file replacement and version-based session revocation. No public setup endpoint, hard-coded credentials, Google credential forms, AI code execution, browser debug server or VNC listener. The app binds only to loopback. Public access requires HTTPS with a trusted certificate; loopback HTTP is supported for an encrypted SSH tunnel. Cookie sessions are HttpOnly and SameSite=Strict, Secure behind TLS, bounded to 8 hours by default (1–24 configurable). The bounded in-memory session store intentionally invalidates all sessions on server restart. It is suitable for one Node process and a single administrator, not a cluster.

Exact Host validation, same-origin CSRF tokens for mutations, authenticated same-origin WebSockets, bounded messages/action queues and failed-login rate limiting. Password resets invalidate existing HTTP/WebSocket identities. The viewer transmits sensitive browser pages to the signed-in administrator; frames are held in memory, not written to screenshots/logs. No login frames go to an AI provider. Logs avoid URLs, page text, passwords and tokens. Preview artifacts in CI contain only the synthetic fixture. Deploy without access logs containing request bodies or session cookies.

Persistent profile and downloads stay under DATA_DIR with private directories. Downloads are served only through authenticated UUID routes with an attachment disposition and nosniff, never as static files; symlinks are excluded. Uploads are memory-bounded and transferred only into a recent active website file chooser. Temporary browser downloads can use disk before the saved-file size check; enforce a VPS disk quota. The browser sandbox is enabled in production and root launch is refused. Headless screenshot streaming requires no public debugging ports. Full-disk encryption and normal VPS hardening remain operational responsibilities.

Navigation and browser requests are restricted to public HTTP/HTTPS addresses; private IPv4/IPv6, loopback, local names, metadata addresses and mixed public/private DNS answers are rejected. Service workers are disabled so interception applies consistently. WebSockets receive the same destination check, and non-proxied WebRTC UDP is disabled. DNS preflight is defense in depth, not a complete network firewall: rebinding or unusual Chromium protocols may evade application checks. For untrusted browsing, use a dedicated VPS without access to private infrastructure and enforce outbound firewall/network-isolation rules blocking all private/link-local/metadata networks, including IPv6. The authenticated administrator can visit untrusted sites, so keep Chromium current and avoid hosting unrelated secrets under this service account.

This is a shared single-administrator browser profile. Every authenticated session controls the same tabs; maximum three simultaneous viewer streams and eight browser tabs. No multiple-user isolation is claimed. Password reset signs viewers out but does not erase website cookies. Stop, restart or inactivity closes tabs; persisted cookies depend on the site. To erase browsing data, stop the app and securely remove only DATA_DIR/profile after backing up anything needed; this signs out websites. Do not delete .env or admin.json merely to clear browser cookies.

The remote browser may be rejected by Google/other services. No stealth patches, security bypasses, MFA/captcha workarounds or cookie transfers are implemented. The app is a website viewer, not a complete remote desktop: no audio/video stream, camera/microphone, drag selection/drag-and-drop, native browser menus or extension installer; native dialogs are dismissed. Keyboard shortcuts are allowlisted; ordinary text/paste works. The streamed website is an image and is not a semantic screen-reader interface. The administration UI itself has labeled controls, keyboard focus and responsive layout.
