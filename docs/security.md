# Security model

Loopback-only listening is validated at startup. HTTPS is required for every app request, including login, and Host must match PUBLIC_ORIGIN. Use a trusted loopback TLS proxy through SSH forwarding or trusted built-in TLS. Trust proxy is loopback, so do not give untrusted local users access to the server. No browser debug or VNC ports are opened. Google credentials go directly to Google through transient WSS frames/input; frames are never persisted, logged, or sent to AI. Monitor screenshots are restricted to worker-only current-response image elements; no page chrome, prompts or login UI.

Admin provision is CLI only, interactive TTY, one singleton indexed identity, Argon2id. Secure/HttpOnly/Strict cookies, Mongo server sessions, one hour rolling expiry, session regeneration, CSRF origin and token checks, rate limits and CSP. Password change invalidates Mongo-backed sessions. In-memory test session store is test-only. Enforce SSH key authentication and a restricted non-root service user; firewall should permit only your intended SSH endpoint initially.

Use umask 077 and 0700 runtime/profile directories. .env is 0600 and outside public static assets. Uploaded images are size-limited and signature-sniffed PNG/JPEG/WebP with decoded pixel bounds, random filenames and normalized display names; no SVG/HTML. Outputs require image signatures, dimensions and authorization. Storage paths validate basenames. Do not place app runtime in a shared/public directory. Backups and browser profiles contain live session credentials; encrypt off-host backups with organization-approved tools and test recovery.

Groq receives compact metadata from controls only, no page text, screenshots, cookies or profile data. Labels are bounded and email-redacted; do not put sensitive data in custom UI labels. Proposal JSON is strict, candidate constrained and operation must equal the requested allowlisted operation. No JavaScript/shell from LLM, no arbitrary model navigation. Domains are HTTPS Google account/Gemini hosts; subresources may load Google assets. Any security challenge or quota stops automation. No stealth plugins or MFA/captcha bypass.

Residual limitations: Gemini selectors and signed-in heuristics need live verification. Display email is an administrator label, not a verified identity claim. A malicious page can manipulate candidate labels; repairs require postconditions and unique targets but cannot eliminate all browser UI ambiguity. The first send click is never auto-retried. File/DB writes aren't transactional; inspect orphan files after a crash. This system is for one trusted administrator on one VPS, not multi-tenant or internet-public shared hosting. Google's service terms and UI may constrain automation; verify permitted usage before deployment.
